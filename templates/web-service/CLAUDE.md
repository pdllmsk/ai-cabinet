# Правила проекта сервиса для интернета

Это папка одного сервиса участника корпоративного курса по Claude. Сервис работает в интернете: коллеги открывают его адрес в браузере, один раз вводят код доступа и работают со страницей. Страница и действия сервиса живут на сайте Vercel, данные в базе Supabase, код в закрытом хранилище GitHub человека. На компьютере человека тот же сервис открывается фразой «покажи сервис», с той же базой. Кабинет человека (папка `ai-cabinet`) показывает карточку сервиса с адресом и кодом. Ты здесь помогаешь сделать, доработать и опубликовать сервис. Этот файл человек знает как «правила проекта», так его и называй.

Не говори человеку терминал, консоль, команда, порт, сервер, Git, коммит, пуш, трейсбек. Без термина не обойтись: поясни его в скобках.

## Как устроен сервис

- Страница `public/index.html` открывается в браузере и просит данные у действий: `POST /api/<действие>`. Действия в `api/index.py` читают и пишут базу через `lib/db.py` и отвечают JSON. Всё остальное (адреса, проверка кода доступа, ответы, ошибки) делает `lib/web.py`.
- На сайте Vercel `api/index.py` запускается на каждый запрос: не дольше 10 секунд, без своих файлов (записать файл на сайте нельзя, всё хранится в базе). На компьютере тот же `api/index.py` запускает `lib/web_dev.py` с ключами из `.env`.
- Кнопки «Запустить» у такого сервиса нет: он работает, пока открыт его адрес. Долгих расчётов на минуты нет: считай запросом к базе или по частям.
- `kind` в `service.json` всегда `web`. Поля `run`, `result`, `page` у этого вида не нужны.

## Действия: api/index.py

```python
import sys
from pathlib import Path

sys.path.insert(0, str(Path(__file__).resolve().parent.parent / "lib"))

from web import serve, StopRun, read_upload  # noqa: E402
from db import query, execute, insert_rows, transaction  # noqa: E402


def tochki(data, file):        # data: JSON со страницы, file: загруженный файл или None
    rows = query("select tochka, vyruchka from app.tochki where nedelya = %s order by vyruchka desc", (data.get("nedelya"),))
    return {"columns": ["Точка", "Выручка"], "rows": [[r["tochka"], r["vyruchka"]] for r in rows]}


class handler(serve({"tochki": tochki})):
    """Вход сервиса для Vercel."""
```

- Действие: функция `fn(data, file)`, возвращает словарь, страница получит его как JSON. `data`: что прислала страница (JSON до 1 МБ). `file`: загруженный файл `{"name": ..., "data": байты}` (до 4 МБ) или `None`.
- Имя действия: строчные латинские буквы, цифры и дефис. Имена `health` и `login` заняты: их отвечает `lib/web.py`.
- Понятная ошибка для человека: `raise StopRun("...")` одной строкой по-русски, страница получит её в поле `error` (ответ 400). Другое исключение: страница получит «Сбой сервиса, подробности в журнале», причина в окне `web_dev` на компьютере или в журнале Vercel.
- В конце файла класс `class handler(serve({...})):` со всеми действиями (именно класс: строку `handler = serve(...)` Vercel не находит): без него сайт не ответит.
- Действие доступно только после кода доступа: это делает `lib/web.py`, сам проверку не пиши и не обходи.

## База: db.py

- `query(sql, params)`: строки списком словарей. `execute(sql, params)`: изменить, ответ: число строк. `insert_rows("app.<таблица>", ["столбец", ...], rows)`: много строк одним вызовом. `with transaction():` несколько изменений вместе: или все, или ни одного.
- Данные в SQL только параметрами: `%s` с кортежем (`query("... where id = %s", (id,))`) или `%(имя)s` со словарём (`{"id": 5}`). Никогда не склеивай SQL со значениями: f-строки, `%`, `+` и `.format` в первом аргументе ловит проверка, и сервис не опубликуется.
- Таблицы только в схеме `app` (`app.zapisi`): её не видит автоматический доступ Supabase из интернета. Схему `public` не используй. Имена таблиц и столбцов латиницей строчными (`vyruchka`, `data_prodazhi`), подписи по-русски на странице.
- Таблицы описываются файлами `db/NNN_<что>.sql` по номерам. Новая таблица или столбец: новый файл со следующим номером (`002_tochki.sql`: `create table if not exists app.tochki (...)`, `alter table app.zapisi add column if not exists ...`). Старые файлы не правь: они уже в базе, изменение в них в базу не попадёт. Нельзя: `drop schema`, права для `anon` и `authenticated`, таблицы вне `app`.
- Типы: деньги и количества `numeric(14, 2)`, целые `integer`, даты `date`, время `timestamptz`, текст `text`, номер строки `id serial primary key`.
- Новые файлы `db/` попадают в базу при «подключи базу» и «опубликуй сервис». Проверить на компьютере новую таблицу можно только после этого. Связь и таблицы: `python lib/db.py check` (на Mac `python3`).
- Базы ещё нет (в `.env` нет адреса базы): `db.py` ответит «База не подключена». Подключи её скиллом `kabinet-podkluchi-bazu` (фраза «подключи базу»): в интернет сервис при этом не выходит.

## Загрузка Excel

- Файл со страницы: действие с `file`, `table = read_upload(file)`: `{"columns": [...], "rows": [[...], ...]}` (Excel или CSV, первый лист или `read_upload(file, sheet="Лист")`). Значения в `rows` текстом: числа разбирай сам (пробелы убрать, запятую в точку), не разобралось: `StopRun` с названием строки.
- Столбцы ищи по названию из шапки, не по номеру. Нужного нет: `StopRun("В файле нужен столбец «Сумма»")`.
- Строки в базу `insert_rows`. Файл заменяет прежние данные (как самый свежий файл в `input/`): в одной `transaction()` сначала `execute("delete from app.<таблица>")`, потом `insert_rows`. Файл дополняет данные: только `insert_rows`. Как именно, реши с человеком в плане.
- Сам файл нигде не сохраняется: в базу попадают только строки. Файл больше 4 МБ: попроси человека разбить его или убрать лишние столбцы.

## Страница: public/

- Страницу собирай только из набора интерфейса кабинета в `public/ui/`, это обязательно. Каталог `lib/ui.md`: прочитай перед работой над страницей. Подключение как в шаблонной `public/index.html`: относительными путями `ui/basecoat.css`, `ui/brand.css`, `ui/kabinet.css`, `ui/kabinet.js`, `ui/tailwind.js`, `ui/basecoat.js`, без косой черты в начале.
- Перед работой над страницей прочитай и `lib/design.md`: как сделать её понятной. Перед показом человеку пройди его чек-лист. Набор `ui.md` главнее: при расхождении следуй ему.
- Таблица: `kabinet.table('#table', {columns, rows})`. Сообщение: `kabinet.toast('Запись добавлена')`, ошибка `kabinet.toast(текст, 'error')`. Числа: `kabinet.number(x)`. Графики только через `kabinet.chart`.
- Данные только через действия: функция `api(имя, данные, файл)` из шаблонной страницы. Она шлёт `POST api/<имя>` (адрес относительный), а на ответ «Нужен код доступа» показывает экран кода и повторяет запрос после входа. Экран кода и эту функцию не убирай и не меняй их поведение.
- Цвета только токенами набора (`bg-card`, `text-muted-foreground`, `var(--primary)`): без `#hex`, `rgb()` и `style` с цветом. Свои библиотеки, шрифты и ссылки на внешние сайты (CDN) нельзя: проверка их ловит, а на компьютерах компании интернет может быть закрыт.
- Страница открыта всем, у кого есть адрес, но данные отдаются только после кода. Поэтому данные в HTML не вписывай: только через действия.

## Код доступа

- У сервиса один код доступа из трёх слов латиницей через дефис (`river-lamp-sun`). Коллега вводит его один раз, браузер помнит его 90 дней. Код заводится при первой публикации, человек видит его в разговоре и на карточке сервиса в кабинете («Показать код»).
- Сменить код: фраза «смени код доступа» (скилл `kabinet-opublikuy`). Старый код сразу перестаёт работать, всем нужно ввести новый.
- Сервис без кода доступа не бывает: не убирай проверку, не делай действия без кода, не вписывай код в страницу или программу. Входа по почте и своих паролей у сотрудников нет.

## Данные и персональные данные

- В этом сервисе персональных данных нет: ФИО, ИИН, телефоны, почта, адреса, паспорта, даты рождения в базу и на страницу не попадают, пока нет письменного согласия юристов или ИБ. Это строже, чем для файлов на компьютере: сервис открыт из интернета. Нужна группировка по человеку: храни код (первые 12 знаков `sha256` от значения), не само значение. Человек говорит, что согласие есть: снять запрет может только тренер курса.
- Коммерческие данные компании (суммы, точки и отделения, контрагенты, цены, залоги и займы) можно.
- Таблицу из `input/` сначала посмотри через `python lib/read_table.py "input/<файл>" --rows 5`: листы, шапка, число строк и первые строки. Посчитать для проверки: итоги `read_table.py` (`--sum`, `--by`, `--where`). Их считает программа на компьютере, это надёжнее подсчёта в разговоре.
- Не выдумывай: значение, которого нет или которое не читается числом, это `None` (в базе `null`), не ноль. Пропуски не досчитывай и средним не заполняй.
- Расчёт от «сегодня» (прошлая неделя, просрочка): назови дату, от которой считаешь. Период бери из данных или из слов человека; в учебном кейсе «сегодня» 09.11.2026. Дату компьютера молча не подставляй.

## Что можно программе

Действия работают в интернете без тебя и без окна разрешения, поэтому правила строгие. Их проверяет `node "<кабинет>/tools/web.mjs" check "."`, и «опубликуй сервис» без исправления сервис не выложит.

- Библиотеки только эти: `json`, `os` (только `os.path` и `os.replace`), `re`, `sys`, `datetime`, `pathlib`, `csv`, `math`, `decimal`, `collections`, `itertools`, `difflib`, `unicodedata`, `zipfile`, `io`, `statistics`, `functools`, `string`, `typing`, `dataclasses`, `copy`, `time`, `calendar`, `textwrap`, `enum`; `openpyxl` для Excel; из `lib/` только `web`, `db`, `read_table`; свои модули рядом с `api/index.py`; для данных с сайтов `urllib`, `http` (без `http.server`), `ssl`, `html`, `xml`, `email`, `base64`, `hashlib`, `gzip`, `uuid`, `random`.
- Нельзя: запускать другие программы (`subprocess`, `os.system`), выполнять текст как программу (`eval`, `exec`), свой сервер или соединения (`http.server`, `socket`), доставать функции по имени (`getattr`, `globals`, `__import__`), читать и писать файлы вне проекта.
- Модели (Claude) в этом сервисе нет: `llm` не подключай. Сервису модель обязательна: скажи человеку, что такой сервис пока делается только для компьютера (фраза «новый сервис» в кабинете, вариант «Только на моём компьютере»).
- Интернет: только если человек просит данные с сайта. Адреса постоянными в начале `api/index.py` (`SOURCES`), у каждого запроса ограничение времени до 5 секунд, сайт не ответил: `StopRun` с понятной причиной.
- SQL только с параметрами, таблицы только `app.` (раздел «База»).

## Секреты

- Пароли, токены и ключи человека не проси и не принимай в чате, в программу не пиши. Прислали в чат: не используй и скажи, что его нужно сменить. Файл `.env` ты не открываешь (закрыто настройками), в git он не уходит.
- Одно исключение, только при публикации по скиллу `kabinet-opublikuy`: адрес базы с паролем, хэш кода доступа и подпись cookie, которые напечатал `web.mjs` (`secret`, `code`), один раз проходят через разговор, чтобы записать их в настройки сайта Vercel коннектором. Пароль создан машиной для одного сервиса и меняется фразой «смени ключ базы». После записи в Vercel эти значения в разговоре не повторяй, в файлы, версии и сообщения не пиши.
- Ключи Supabase (`service_role`, `secret`) и автоматический доступ к базе из браузера сервису не нужны: не заводи их.

## Как делать сервис

1. Пойми задачу: что видят коллеги, что они вносят или загружают, что сервис считает и показывает. Чего не хватает, спроси. Попроси известный ответ: одно-два числа или факта, которые человек точно знает для этих данных. Нет: посчитай его итогами `read_table.py` по файлу из `input/`, покажи человеку и спроси, сходится ли.
2. Посмотри устройство файлов в `input/` (раздел «Данные»). Есть персональные данные: раздел «Данные и персональные данные», реши с человеком, что убрать.
3. Скажи план пятью-семью строками: таблицы базы и их столбцы, действия, что на странице, как попадают данные (форма, загрузка Excel). Спроси «Так?».
4. Таблицы: новый файл `db/NNN_<что>.sql`. Действия: `api/index.py`. Страница: `public/index.html`. Пример шаблона (`zapisi`, `dobav`, `zagruzka`) замени своим. `service.json`: `name` и `about` одной фразой.
5. Проверка правил: `node "<кабинет>/tools/web.mjs" check "."`. Нашлось: исправь и проверь снова.
6. Покажи сервис на компьютере (раздел «Показать и опубликовать»), загрузи данные через страницу или действие и сверь с известным ответом, до слова «готово»: числа на странице, итоги `read_table.py` по тому же файлу. Не совпало: найди причину (столбец, период, формат чисел, пропуски), исправь, проверь снова. Человеку скажи, что сверил и с чем.
7. Что-то не сошлось с первого раза (число разошлось с известным ответом, не тот столбец или период, особые строки в данных, сбой действия или проверки): запиши урок в раздел «Уроки» ниже, до ответа человеку, и скажи ему одной фразой, что записал.
8. В конце: «Сервис готов. Чтобы коллеги открывали его по ссылке, скажите «опубликуй сервис».» Уже опубликован: «Скажите «опубликуй сервис», и изменения появятся на сайте.»

«Доработай», «почини сервис», «поменяй ...»: те же шаги 2-8 для изменения.

## Показать и опубликовать

Папку кабинета `<кабинет>` находи так же, как скилл `kabinet-opublikuy` (раздел «Где кабинет»): путь, из которого поставлен скилл, иначе поиск `Documents/ai-cabinet` и `Документы/ai-cabinet` в домашней папке, иначе спроси человека. Пути в командах в кавычках.

- **«Покажи сервис»**, «открой сервис», «запусти страницу»: `node "<кабинет>/tools/web.mjs" dev "." --json`, ответ: `url` и `pid`. Назови адрес целиком и попроси открыть его в браузере. Страница работает с той же базой, что сайт: всё, что внесёте на компьютере, видно и коллегам. Код доступа для входа: на карточке сервиса в кабинете («Показать код»). Остановить: на Windows `taskkill /PID <pid> /F`, на Mac `kill <pid>`; уже запущена в этом разговоре: второй раз не запускай, назови адрес.
