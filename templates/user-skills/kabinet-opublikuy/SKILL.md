# Опубликовать сервис

Сервис для коллег живёт в интернете: страница и действия на сайте Vercel, данные в базе Supabase, код в закрытом хранилище GitHub человека. Коллеги открывают адрес и один раз вводят код доступа. Этот скилл выкладывает сервис туда и обновляет его. Аккаунты человек подключил один раз фразой «подключи публикацию».

Человек не разработчик: говори просто, без слов команда, терминал, скрипт, сервер, порт, Git, коммит, деплой. Вместо них: «сохраняю версию», «отправляю на сайт», «сайт обновляется». Сырой вывод и ответы коннекторов не показывай, пересказывай. По ходу работы короткие строки, что делаешь: «Создаю базу, это 1-3 минуты».

Каждый шаг сначала проверяет, сделан ли он (по `web.mjs status` и ответам коннекторов), и сделанное пропускает. Поэтому после сбоя или нового разговора та же фраза продолжает с первого невыполненного шага. Вопросы человеку только там, где они написаны ниже.

## 1. Где кабинет и папка сервиса

Папку кабинета `ai-cabinet` дальше зову `<кабинет>`, папку сервиса `<проект>`. Пути в командах всегда в кавычках и без косой черты в конце: в них бывают кириллица и пробелы.

Кабинет:

- Разговор открыт в самом кабинете (в его папке лежат `START.md` и `tools/services.mjs`): кабинет это папка разговора.
- Иначе бери папку, из которой поставлен этот скилл: `{{KABINET}}`. Видишь вместо пути слово в двойных фигурных скобках: скилл поставлен не кабинетом, переходи к следующему пункту.
- Команда кабинета ответила `Cannot find module` (файла нет) или пути выше нет: найди кабинет одной командой. Она смотрит переменную среды `AI_CABINET_DIR`, затем `Documents/ai-cabinet` и `Документы/ai-cabinet` в домашней папке (и в OneDrive) и печатает путь или «нет»:

  ```
  node -e "const f=require('fs'),p=require('path'),h=require('os').homedir();const c=[process.env.AI_CABINET_DIR,p.join(h,'Documents','ai-cabinet'),p.join(h,'Документы','ai-cabinet'),p.join(h,'OneDrive','Documents','ai-cabinet'),p.join(h,'OneDrive','Документы','ai-cabinet')].filter(Boolean);console.log(c.find(x=>f.existsSync(p.join(x,'tools','services.mjs')))||'нет')"
  ```

- Ответ «нет»: спроси «Где лежит папка вашего кабинета ai-cabinet? Откройте её в Проводнике, щёлкните по адресной строке вверху, скопируйте путь и вставьте сюда.»

Проект: папка этого разговора, если в ней есть `service.json`.

Разговор открыт в кабинете: найди папку названного сервиса через `node tools/services.mjs list` (не назван: спроси, какой). Здесь можно сказать состояние (раздел 2): опубликован ли, адрес. Всё, что меняет сайт, делай в разговоре в папке сервиса: настройки кабинета закрывают отправку кода в интернет из кабинета, это защита шаблона курса. Скажи: «Откройте папку сервиса <путь> в новом разговоре: в приложении Claude **Code** (вкладка Code) → **Local** (на этом компьютере) → **Open folder…** (открыть папку), в VS Code **File** (файл) → **Open Folder…** (открыть папку). Там скажите «<фраза человека>».» Дальше не иди.

Окна разрешения: перед первым действием скажи одной фразой: «Сейчас Claude может несколько раз попросить разрешение на действия кабинета, коннекторов и сохранение версий. Нажимайте **Allow** (разрешить).»

## 3. Правила для всех шагов

- **Ключи (единственное исключение из правила «секреты не в чате»).** Пароль базы, хэш кода доступа и подпись cookie создаёт `web.mjs` на компьютере и пишет в `.env` проекта. Сайту Vercel их можно передать только коннектором, поэтому они один раз проходят через разговор: берёшь их только из вывода `web.mjs secret --json` и `web.mjs code --json` (файл `.env` закрыт для чтения, не открывай его), сразу передаёшь в `create_project_env` и после записи в Vercel в разговоре больше не повторяешь: ни человеку, ни в файлы, ни в версии, ни в сообщения. Код доступа (три слова) человеку сказать можно и нужно: это не пароль базы.
- **Имена.** Имя сервиса для GitHub, Vercel и Supabase: имя папки проекта латиницей (`svetofor-tochek`). Занято: `-2`, `-3`.
- **Паспорт.** Что создано, сразу записывай в блок `publish` в `service.json` (правка файла): так следующий запуск не создаст второе. Поля: `github` (`"<логин>/<имя>"`), `vercel_project`, `url`, `supabase_ref`, `db_host` (адрес пула базы), `published_at` (время в формате ISO с часовым поясом). Ключей и паролей в `service.json` нет.
- **Сохранить версию:** `git add -A`, затем `git commit -m "<что сделано>"`. Отправить на сайт: `git push`. Нечего сохранять: это не ошибка, иди дальше.
- **Автор версий.** Бесплатный Vercel не собирает сайт, если автор версии не связан с аккаунтом GitHub человека (сборка в состоянии `BLOCKED`). Поэтому перед первой версией в этой папке поставь автором служебную почту GitHub: число `id` из `get_me` коннектора GitHub (нет коннектора: открой `https://api.github.com/users/<логин>`, поле `id`), затем `git config user.name "<логин>"` и `git config user.email "<id>+<логин>@users.noreply.github.com"` (только в этой папке, без `--global`). Сборка `BLOCKED`: проверь автора (`git log -1 --format=%ae`), поставь его так и сохрани пустую версию «Публикация».
- **Ожидание.** Между опросами коннектора (база создаётся, сайт обновляется) жди около 15 секунд, не дольше 5 минут на шаг. Человеку одна строка, что ждёшь.
- **Коннектор ответил ошибкой входа:** «Вход в <Vercel> истёк: в приложении Claude **Settings** (настройки) → **Connectors** (коннекторы) → <Vercel> → **Connect** (подключить). Напишите «готово».» Потом повтори этот же шаг.
- **Не делай:** не меняй `lib/`, `public/ui/`, `vercel.json`, `.claude/` (их кладёт кабинет); хранилище GitHub только закрытое (`private`), открытым не делай никогда; базы и проекты не удаляй; другой проект Supabase на паузу только после выбора человека (раздел 10).

## 4. Перевод в интернет (сервис вида run или page)

Сервис сейчас считает файлы на компьютере, кнопкой «Запустить» в кабинете. Переводишь его в интернет-версию: данные в базу, расчёт в действия сайта, страница в `public/`. Для человека это одна фраза и одно нажатие.

1. **Модель.** В `main.py` или `api.py` есть `import llm`, `from llm` или `ask_model(`: «Этот сервис обращается к модели Claude, а в интернет-версии модели пока нет. Он остаётся на компьютере и работает из кабинета, как раньше.» Стоп.
2. **Персональные данные:** раздел 11. Человек выбрал «Оставить сервис на компьютере»: стоп.
3. **Один вопрос**, окном (AskUserQuestion), варианты «Да (рекомендую)» и «Не сейчас»:
   «Сервис сейчас считает файлы на вашем компьютере. Чтобы коллеги открывали его по ссылке, перенесу данные в базу, а расчёт и страницу в интернет-версию. На компьютере всё продолжит работать. Переносим?»
   «Не сейчас»: «Хорошо, сервис остаётся как есть.» Стоп. Дальше вопросов нет до итога (кроме кнопок входа и раздела 10).
4. **Версия до перевода.** Истории версий нет (`git` в `status` пустой): `node "<кабинет>/tools/services.mjs" upgrade "<проект>"`, она её заведёт. Затем сохрани версию «Сервис до перевода в интернет» и поставь метку `git tag do-perevoda` (метка уже есть: не трогай).
5. **Известный ответ.** Запусти старый расчёт `python main.py` (на Mac `python3 main.py`) и сохрани копию `output/result.json` как `output/result-do-perevoda.json`. С ним сверишь интернет-версию.
6. **Каркас.** Из `<кабинет>/templates/web-service/` перенеси в проект то, чего в нём нет: `api/index.py`, `public/index.html`, `db/001_init.sql`, `vercel.json`, `.python-version`, `requirements.txt` (прочитай и запиши как есть). В `service.json`: `"kind": "web"`, `"api": "api/index.py"`, `"public": "public/"`, `"db": "db/"`; поля `run`, `result`, `input`, `page` убери (они остались в версии до перевода), `name` и `about` оставь. Затем `node "<кабинет>/tools/services.mjs" upgrade "<проект>"`: кабинет положит помощников (`lib/web.py`, `lib/db.py`, `lib/web_dev.py`, драйвер базы), набор интерфейса `public/ui/`, правила и настройки вида `web`. Правила проекта сменились: прочитай новый `CLAUDE.md` проекта целиком и дальше соблюдай его. `main.py`, `api.py`, `page/` пока остаются на месте.
7. **Устройство.** `node "<кабинет>/tools/web.mjs" migrate-plan "<проект>" --json`: файлы `input/` с листами и столбцами, предложенные таблицы и типы (`tables`), есть ли своя страница (`page`) и действия (`api`). По нему:
   - `db/001_init.sql`: таблицы `app.<имя>` по файлам `input/`, имена латиницей, типы по данным (деньги `numeric(14, 2)`, даты `date`, текст `text`). Столбцы с персональными данными по выбору из раздела 11. Файл ещё не был в базе, поэтому пример шаблона в нём просто замени.
   - У сервиса уже есть база («подключи базу»: в паспорте было `"db": "db/"` и `publish.supabase_ref`): это та же база, вторую не создавай. Файлы `db/`, которые уже в базе (`list_migrations`), не меняй; таблицы для файлов `input/`, которых в базе ещё нет, новым файлом со следующим номером. Расчёт, который уже брал данные из базы (`from db import ...`), переносится в `api/index.py` как есть.
   - `api/index.py`: расчёт из `main()` в действия, данные из базы (`query`) вместо файлов `input/`. Главное действие (например `itog`) отдаёт то же, что было в `result.json`: `summary`, `columns`, `rows`, `row_status`, `row_note`. Действие `upload` загружает Excel: `read_upload(file)`, затем строки в таблицу через `insert_rows`. Раньше сервис брал самый свежий файл: тогда `upload` в одной `transaction()` очищает таблицу и вставляет строки файла.
   - `public/`: своя страница из `page/` переносится в `public/` как есть, меняются только адреса: `../output/result.json` и `../api/<действие>` на вызов `api('<действие>')` (функция `api()` как в шаблонной `public/index.html`, с экраном кода доступа), `../../../ui/...` на `ui/...`. Своей страницы не было: шаблонная страница с итогом и таблицей главного действия (`kabinet.table`) и загрузкой Excel.
8. **База и проверка:** раздел 5, шаги 1 и 3-7 (база уже подключена: шаги 3-5 только проверят её и применят новые файлы `db/`). Затем загрузи в базу текущие файлы `input/`, которые брал старый расчёт и которых ещё нет в базе, через страницу на компьютере (раздел 5, шаг 7, с тем же кодом):

       curl -s -b "output/.cookie" -H "Content-Type: application/octet-stream" -H "X-File-Name: <имя файла латиницей или в %-кодировке>" --data-binary "@input/<файл>" <адрес>api/upload

9. **Сверка.** Вызови главное действие на компьютере и сравни с `output/result-do-perevoda.json`: числа итога (`summary`), столбцы и строки таблицы. Совпало: дальше. Не совпало: ищи причину (типы столбцов, пропуски, период, округление), исправляй и сверяй снова, пока не совпадёт. Человеку только итог: «Сверил: <итог>, совпадает со старым расчётом.» Спроси человека, только если причина в самих данных и решить её может только он. Расхождение записывай в раздел «Уроки» правил проекта.
10. **Публикация:** раздел 5, шаги 8-12.
11. **Старое в `old/`.** `git mv main.py old/main.py`, так же `api.py` и `page` (что есть). Не удаляй. Сохрани версию «Сервис переехал в интернет» и отправь на сайт (`git push`).
12. **Карточка.** Сервис был в кабинете (`node "<кабинет>/tools/services.mjs" list`): `node "<кабинет>/tools/services.mjs" add "<проект>"`, карточка станет карточкой сайта.
13. **Итог:** как в разделе 5, шаг 13, и строка «Сервис переехал: данные в базе, на компьютере он открывается кнопкой «Показать на компьютере» на карточке в кабинете. Файлы в папке input не тронуты.»

## 5. Публикация (сервис вида web)

1. **Проверка.** `node "<кабинет>/tools/web.mjs" check "<проект>" --json`. `ok: true`: дальше. Иначе в `problems` файл, строка и причина: исправь (SQL только с параметрами, без ссылок на внешние сайты на странице, таблицы только `app.`) и проверь снова. Причина в `lib/` или `public/ui/`: не трогай, скажи «обнови кабинет» в кабинете или позови тренера.
2. **Персональные данные:** раздел 11.
3. **База.**
   - `publish.supabase_ref` есть: `get_project` (`id` = ref). `ACTIVE_HEALTHY`: дальше. На паузе (`INACTIVE`, `PAUSED`): `restore_project`, человеку «База сервиса спала, бужу её, это 1-3 минуты», опрос `get_project` до `ACTIVE_HEALTHY`. Ответ про лимит активных проектов: раздел 10.
   - Нет: `get_cost` (`type` `"project"`, `organization_id` из `publikaciya.json`). Не `$0`: «База в этой организации платная, такую не создаю», позовите тренера, стоп. `$0`: человеку «База бесплатная. Создаю базу, это 1-3 минуты.», затем `create_project` (`name` = имя сервиса, `region` из `publikaciya.json`, обычно `eu-central-1`, `organization_id`). Ответ просит подтверждение стоимости: `confirm_cost` (`type` `"project"`, `recurrence` `"monthly"`, `amount` `0`), затем снова `create_project` с `confirm_cost_id`. Ответ про лимит: раздел 10. Создан: сразу `publish.supabase_ref` = его `id` в `service.json`. Опрос `get_project` до `ACTIVE_HEALTHY`, не дольше 5 минут; дольше: позовите тренера.
4. **Ключ базы.** Адрес пула: `publish.db_host`, иначе из ответа `get_project`, если в нём есть адрес `*.pooler.supabase.com`, иначе `aws-0-<регион>.pooler.supabase.com`.

       node "<кабинет>/tools/web.mjs" secret "<проект>" --ref <ref> --host <адрес пула> --json

   Ответ: `role` (роль базы сервиса), `sql` (создание роли с хэшем пароля, самого пароля в нём нет), `database_url` и `cookie_secret` (для шага 9). Затем `execute_sql` (`project_id` = ref, `query` = `sql`). Повторный `secret` без `--rotate` пароль не меняет, его SQL можно выполнить снова. Запиши `publish.db_host`.
5. **Таблицы.** `list_migrations` (`project_id` = ref): имена уже применённых. Каждый файл `db/NNN_*.sql` по порядку номеров, которого там нет: прочитай и `apply_migration` (`project_id`, `name` = имя файла без `.sql`, например `001_init`, `query` = текст файла). Уже применённые файлы не меняй и не применяй снова.
6. **Код доступа.** `node "<кабинет>/tools/web.mjs" code "<проект>" --json`: `{code, hash}`. Без `--rotate` уже заведённый код не меняется, команда печатает его снова. Код (три слова) скажешь человеку в итоге, `hash` для шага 9.
7. **Проверка на компьютере.**

       node "<кабинет>/tools/web.mjs" dev "<проект>" --json

   Ответ: `url` (адрес на компьютере) и `pid`. Затем по очереди:

       curl -s <url>api/health
       curl -s -c "output/.cookie" -H "Content-Type: application/json" -d "{\"code\":\"<код>\"}" <url>api/login
       curl -s -b "output/.cookie" -H "Content-Type: application/json" -d "{}" <url>api/<главное действие>

   Первый `{"ok": true}`, второй без `error`, третий данные без `error`: база отвечает, дальше. В ответе действия ошибка подключения к базе (не пускает, нет ответа, неверный адрес): адрес пула не тот. Был `aws-0-...`: повтори шаг 4 с `aws-1-<регион>.pooler.supabase.com` и `--rotate` (новый `sql` снова в `execute_sql`), перезапусти и проверь снова. Не помогло: позовите тренера. После проверки останови страницу: на Windows `taskkill /PID <pid> /F`, на Mac `kill <pid>`.

Напишите «готово».», потом повтори. Запиши `publish.vercel_project`.

Сервис закрыт своим кодом доступа, второй замок не нужен.

За 2 минуты новой сборки нет: Vercel не видит хранилище, ссылка из шага 9. `BLOCKED`: автор версии не тот, пункт «Автор версий» выше. `ERROR`: `list_deployment_events` (`idOrUrl` = id сборки, `builds: 1`, `teamId`), найди причину, исправь в проекте, сохрани версию, отправь, жди снова. ## 10. Лимит бесплатных баз

У бесплатного Supabase две активные базы на человека. Ответ `create_project` или `restore_project` про лимит активных проектов:

1. `list_projects`: активные проекты (`ACTIVE_HEALTHY`) с названиями.
2. Окно «В бесплатном Supabase уже две активные базы. Как поступим?»: по варианту «Поставить на паузу «<проект>»» на каждый активный (в описании: «сервис «<проект>» перестанет отвечать данными, вернуть можно фразой «опубликуй сервис» в его папке») и «Отложить публикацию».
3. Только после выбора: `pause_project` выбранного, опрос `get_project` до паузы, затем повтори создание или пробуждение. «Отложить»: «Хорошо, публикацию отложили. Скажите «опубликуй сервис», когда решите.» Стоп.

Сам, без выбора человека, ничего на паузу не ставь.
