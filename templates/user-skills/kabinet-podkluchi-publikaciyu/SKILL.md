# Подключить публикацию

Один раз за курс человек подключает свои бесплатные аккаунты GitHub, Vercel и Supabase. Потом любой сервис для коллег выходит в интернет одной фразой «опубликуй сервис» в папке сервиса. Сам сервис здесь не публикуется: этот скилл только проверяет связь и аккаунты и записывает, куда публиковать.

Человек не разработчик: говори просто, без слов команда, терминал, скрипт, сервер, порт, Git. Сырой вывод и ответы коннекторов не показывай, пересказывай. Шаги по одному: каждый сначала проверяет, сделан ли он, и сделанное пропускает. Ответ человека ждёшь, только когда он должен что-то нажать.

## 1. Где кабинет

Папку кабинета `ai-cabinet` дальше зову `<кабинет>`. Пути в командах всегда в кавычках и без косой черты в конце: в них бывают кириллица и пробелы.

- Разговор открыт в самом кабинете (в его папке лежат `START.md` и `tools/services.mjs`): команды пиши от неё, `node tools/check.mjs ...`, `node tools/web.mjs ...`.
- Иначе бери папку, из которой поставлен этот скилл: `{{KABINET}}`. Видишь вместо пути слово в двойных фигурных скобках: скилл поставлен не кабинетом, переходи к следующему пункту.
- Команда кабинета ответила `Cannot find module` (файла нет) или пути выше нет: найди кабинет одной командой. Она смотрит переменную среды `AI_CABINET_DIR`, затем `Documents/ai-cabinet` и `Документы/ai-cabinet` в домашней папке (и в OneDrive) и печатает путь или «нет»:

  ```
  node -e "const f=require('fs'),p=require('path'),h=require('os').homedir();const c=[process.env.AI_CABINET_DIR,p.join(h,'Documents','ai-cabinet'),p.join(h,'Документы','ai-cabinet'),p.join(h,'OneDrive','Documents','ai-cabinet'),p.join(h,'OneDrive','Документы','ai-cabinet')].filter(Boolean);console.log(c.find(x=>f.existsSync(p.join(x,'tools','services.mjs')))||'нет')"
  ```

- Ответ «нет»: спроси «Где лежит папка вашего кабинета ai-cabinet? Откройте её в Проводнике, щёлкните по адресной строке вверху, скопируйте путь и вставьте сюда.»

Действия кабинета могут спросить разрешение (это зависит от режима, который выбрал человек). Перед первым скажи одной фразой: «Сейчас Claude может несколько раз попросить разрешение на действия кабинета и коннекторов. Нажимайте **Allow** (разрешить).»

## 2. Связь с интернетом

    node "<кабинет>/tools/check.mjs" --net --json

Ответ: список строк проверки. Нужны две, по полю `id`:

- `net-publish`: связь с GitHub, Vercel и Supabase. `status` `ok`: ✓. Иначе в поле `hosts` адреса с `ok: false`. Скажи человеку, что публикация без них не заработает, и дай текст для ИТ, который он перешлёт как есть: «Для работы с сервисами курса прошу открыть доступ к адресам github.com, api.github.com, vercel.com, *.vercel.app, api.vercel.com, supabase.com, *.supabase.co и *.pooler.supabase.com:6543.» Дальше не иди: когда ИТ откроет, человек скажет «подключи публикацию» снова.
- `pushguard`: «Публикация кабинета закрыта». `ok`: ✓. `fail`: шаг 3. Строки нет: кабинет не из шаблона курса или без истории версий, закрывать нечего, тоже ✓.

Остальные строки (обновления, пакеты) здесь не нужны, о них не говори.

## 3. Закрыть публикацию кабинета

Только если строка `pushguard` была `fail`:

    node "<кабинет>/tools/init.mjs"

Затем снова `node "<кабинет>/tools/check.mjs" --json` и строка `pushguard`. Стала `ok`: ✓. Осталась `fail`: ✗, скажи «Кабинет пока не закрыт от публикации, это поправит тренер» и иди дальше: сервисам это не мешает.

Человеку одной фразой: «Кабинет курса в интернет не публикуется: это защита, публикуются только ваши сервисы.»

## 4. Коннекторы

Коннектор: подключение Claude к сайту (GitHub, Vercel, Supabase) под аккаунтом человека. Проверь каждый пробным вызовом:

| Коннектор | Пробный вызов | Нужен для |
|---|---|---|
| Vercel | `get_auth_user` | сайт сервиса |
| Supabase | `list_organizations` | база сервиса |
| GitHub | `get_me` | создать хранилище кода сервиса (`create_repository`) |

Инструментов коннектора нет в списке или вызов ответил ошибкой входа (не авторизован, вход истёк): скажи одной фразой, где нажать, и жди «готово»:

«Подключите <Vercel>: в приложении Claude **Settings** (настройки) → **Connectors** (коннекторы) → <Vercel> → **Connect** (подключить), в окне браузера **Authorize** (разрешить). Входите через GitHub. Напишите «готово».»

После «готово» повтори пробный вызов. Claude по-прежнему не видит коннектор: «Начните новый разговор в этой же папке и снова скажите «подключи публикацию»: новые коннекторы видны в новом разговоре.» Коннектора нет в списке **Connectors** совсем: его не разрешил администратор, позовите тренера.

Vercel и Supabase обязательны: без них дальше не иди. GitHub нет и не подключается: не стоп. Логин GitHub возьмём из Vercel (шаг 5), а хранилище кода при публикации создаётся по ссылке одним нажатием. Скажи: «Без коннектора GitHub при первой публикации каждого сервиса я дам ссылку: на ней одна кнопка **Create repository** (создать хранилище). Подключить GitHub можно позже так же: Settings → Connectors → GitHub → Connect.»

## 5. Vercel: команда и связь с GitHub

1. Команда (`teamId`): `list_teams`. Одна команда: её `id`. Несколько: спроси окном, какую взять (личную первой с пометкой «(рекомендую)»). Список пустой (так на бесплатном тарифе Hobby): `get_auth_user` → `user.defaultTeamId`. Нет и его: ✗, позовите тренера.
2. Логин GitHub: `git_namespaces` с `provider` `"github"`. Нужна запись с `ownerType` `"user"`: её `slug` (или `name`) и есть логин. Коннектор GitHub подключён: сверь с `login` из `get_me`; не совпали, бери логин из `get_me` и проверь, что он есть в списке.
3. Записи нет (или нет логина из `get_me`): Vercel не видит GitHub человека. Скажи: «Откройте ссылку https://github.com/apps/vercel/installations/new, выберите свой аккаунт, отметьте **All repositories** (все хранилища) и нажмите **Install** (установить). Напишите «готово».» После «готово» повтори пункт 2.
4. Право коннектора создавать проекты в этой команде: `list_projects` с `teamId` и `limit` `"1"`. Ответ 403 или ошибка с `authorize_team_access` (так бывает даже у личного аккаунта Hobby): вызови `authorize_team_access` с этим `teamId`, ссылку из ответа дай человеку: «Откройте ссылку и нажмите **Approve** (разрешить): так Claude сможет выкладывать ваши сервисы в Vercel. Ссылка работает 10 минут. Напишите «готово».» После «готово» повтори `list_projects`. Опять 403: ✗, позовите тренера.

## 6. Supabase: организация

1. `list_organizations`. Одна: её `id`. Несколько: спроси окном, какую взять. Нет ни одной: «Откройте https://supabase.com/dashboard/new, создайте организацию (тариф **Free**, бесплатный) и напишите «готово».» Потом повтори.
2. `get_cost` с `type` `"project"` и `organization_id`. `$0`: ✓. Не ноль: база в этой организации платная, такую не создаём. Скажи сумму и предложи позвать тренера; в итоге ✗.

## 7. Записать

    node "<кабинет>/tools/web.mjs" save-account --github <логин> --vercel-team <teamId> --supabase-org <id организации>

Команда пишет `me/publikaciya.json` в кабинете: логин GitHub, команду Vercel, организацию Supabase, регион базы `eu-central-1` и время проверки. Это не ключи и не пароли. Файл в папке `me/`: обновление кабинета его не трогает. Сам файл не правь.

## 8. Итог

Пять строк ✓ или ✗, без технических подробностей:

```
✓ Связь с GitHub, Vercel, Supabase
✓ Кабинет закрыт от публикации
✓ GitHub: <логин> (хранилища создаю сам | по ссылке, коннектора нет)
✓ Vercel: сайты сервисов
✓ Supabase: базы сервисов, бесплатно
```

Всё ✓ (GitHub без коннектора тоже ✓): «Публикация подключена. Теперь в папке сервиса скажите «опубликуй сервис». Сервиса для коллег ещё нет: скажите «новый сервис».»
Есть ✗: что не так одной фразой и что сделать (позвать тренера или повторить «подключи публикацию» после ИТ).

Что ещё бывает:

- `Cannot find module`: кабинет не там, вернись к разделу 1.
- Node не найден: «На компьютере нет программы Node.js, без неё кабинет не работает. Позовите тренера.»
- Человек не разрешил действие: скажи, что без него публикацию не подключить, и спроси, повторить ли.
- Другая ошибка: перескажи своими словами и предложи позвать тренера. Пароли и ключи у человека не проси: коннекторы входят сами.
